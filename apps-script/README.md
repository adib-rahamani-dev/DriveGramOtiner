# انتقال رایگان روی سرور گوگل

مسیر فایل: آپلود شما به پوشهٔ خصوصی Drive → اجرای Apps Script در حساب خودتان روی سرور گوگل → دریافت فایل اصلی در پی‌وی `@DriveGramOtiner_bot`. در زمان انتقال، برنامه و VPN کامپیوتر شخصی لازم نیستند. این اجرا مستقل از دیتابیس و پنل محلی است؛ وضعیت معتبر آن در خود ربات با `/videos` دیده می‌شود.

## راه‌اندازی

1. در حساب صاحب پوشه، پروژهٔ خصوصی Google Apps Script بسازید. کد `Code.gs` را در ویرایشگر ذخیره کنید و manifest را از `appsscript.json` وارد کنید. manifest سرویس Drive v3 را هم فعال می‌کند؛ در پروژهٔ پیش‌فرض Apps Script، API متناظر خودکار فعال می‌شود. پروژه را عمومی یا share نکنید.
2. در **Project Settings → Script Properties**، `BOT_TOKEN`، `PRIVATE_CHAT_ID` مثبت مربوط به پی‌وی تأییدشدهٔ خودتان، و `DRIVE_FOLDER_ID` همان پوشه را ذخیره کنید. کلیدها در کد و Git قرار نمی‌گیرند. OAuth client secret و refresh token برنامهٔ محلی لازم نیست.
3. worker کامپیوتر و هر گیرندهٔ دیگر همین ربات را متوقف کنید؛ دو اجرای مستقل، دفتر ارسال مشترک ندارند. قبل از شروع، وضعیت ارسال‌های قبلی و عدم وجود فایل متناظر را بررسی کنید.
4. تابع `installDriveGram` را با مجوزهای اعلام‌شده اجرا کنید: خواندن Drive، درخواست HTTP خارجی برای ارسال به Telegram و ایجاد trigger در همین پروژه. هیچ مجوز نوشتن یا حذف Drive در manifest وجود ندارد. در اولین اجرا خود صاحب حساب باید مجوز گوگل را بررسی و تأیید کند.
5. نصب، هویت ربات و خصوصی‌بودن مقصد را بررسی می‌کند، در صورت وجود webhook قبلی متوقف می‌شود و یک trigger دقیقه‌ای می‌سازد. هر بار حداکثر یک فایل کامل ارسال می‌شود. فایل‌های موجود پوشه نیز به‌صورت خودکار انتخاب می‌شوند؛ هیچ تغییری در اصل Drive داده نمی‌شود.
6. اجرای واقعی `drivegramTick` و دریافت پیام فایل با پاسخ موفق Telegram را تأیید کنید. صرف ذخیرهٔ کد یا نصب trigger اثبات ارسال نیست.

## وضعیت و جلوگیری از تکرار

وضعیت هر نسخه از فایل در Script Properties خصوصی نگهداری می‌شود. پیش از ارسال، طول، checksum و تعلق نسخه به پوشه بررسی می‌شود. lock مانع اجرای هم‌زمان trigger و اجرای دستی می‌شود. قبل از درخواست ارسال، وضعیت `sending` ذخیره می‌شود؛ قطع اتصال یا اتمام اجباری اجرا این نسخه را از انتخاب خودکار خارج می‌کند. در `/videos` ابتدا «بررسی فایل» و فقط پس از بررسی پی‌وی و اطمینان از نرسیدن، «بررسی کردم؛ فایل نرسیده — تلاش مجدد» را بزنید. پاک‌کردن پروژه یا Script Properties سابقهٔ جلوگیری از تکرار را از بین می‌برد.

## محدودیت‌ها

- سقف امن نسخهٔ فعلی **۴۹٬۰۰۰٬۰۰۰ بایت** است؛ به‌دلیل سقف ۵۰ مگابایتی POST گوگل باید برای multipart هم جا باقی بماند. فایل بزرگ‌تر رد می‌شود، تقسیم یا تبدیل نمی‌شود؛ این راهکار برای ویدیوهای ۳۰۰ مگابایتی نیست.
- هر اجرای Apps Script حداکثر ۶ دقیقه و مجموع triggerهای حساب شخصی حداکثر ۹۰ دقیقه در روز است. trigger دقیقه‌ای زمان دقیق یا سرعت تضمین‌شده ندارد. تعداد فایل‌ها و سرعت شبکه باید با این سهمیه‌ها سازگار باشند.
- فهرست حداکثر ۵۰۰ ویدیوی فرزند مستقیم پوشه را پوشش می‌دهد. زیرپوشه‌ها پشتیبانی نمی‌شوند. Script Properties سقف ۵۰۰ کیلوبایت دارد؛ این نسخه برای آرشیو نامحدود و بار سنگین طراحی نشده است.
- پروژهٔ Google Apps Script مجوز جداگانه دارد؛ اتصال OAuth پنل محلی به آن منتقل نمی‌شود. اجرای جدید از مجوز خود حساب گوگل استفاده می‌کند.
- لاگ‌ها نام، شناسه یا توکن فایل‌ها را چاپ نمی‌کنند. ربات فهرست و دکمه‌ها را تنها در پی‌وی صاحب حساب می‌پذیرد.

منابع رسمی: [سهمیه‌های Google Apps Script](https://developers.google.com/apps-script/guides/services/quotas)، [UrlFetchApp و ارسال blob در فرم](https://developers.google.com/apps-script/reference/url-fetch/url-fetch-app)، [triggerهای زمان‌بندی‌شده](https://developers.google.com/apps-script/guides/triggers/installable).
